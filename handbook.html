Pipeline, step by step

Each step: what it is, what goes in, what comes out, who owns it, a teaching note, a checklist.

1. Website

This is the product the jury watches. Three buttons: Single image, Before/After, Optical+SAR. Upload, question box, Run. Then: preview, answer, overlay, confidence, tool receipt, download.

In: files + question. Out: whatever JSON the API returned, drawn on screen. The website does not decide the answer.

Teach Use a map library if you can (MapLibre). For 12 Sep, an image viewer plus a slider is enough. The receipt panel is not decoration. ISRO said they score the visible execution summary, not hidden thinking.

2. API

Front door. FastAPI is enough. Two calls: upload files, then query. Everyone else talks JSON, not each other’s Python internals.

{
  "task": "single_image | change | optical_sar | reject",
  "tools": ["checker_v1", "change_tool_v1"],
  "parameters": { "threshold": 0.63 },
  "facts": {},
  "answer_text": "Built-up area increased (~12.4 ha).",
  "confidence": 0.74,
  "warnings": [],
  "overlay": { "type": "change_mask", "file": "..." },
  "receipt": { "why_this_tool": "two dated images + change question", "rejected": false }
}

M4, M5, M6 fill facts, confidence, overlay. M1 writes answer_text. M2 only displays.

3. Checker

Reads the file like a customs officer. If the pair is not the same place, it stops. Guessing alignment is how you fail the “trustworthy” test.

Look at: format, width/height, band count, data type, CRS (map projection), bounds, transform, nodata, dates if present. Optical vs SAR: from metadata or band pattern. If unsure, ask the user. Do not silently treat radar as RGB.

Teach: GeoTIFF A normal JPEG is a grid of colours. A GeoTIFF is that grid plus “this pixel is this place on Earth.” CRS tells you which map system (often EPSG:4326 lat/long, or a UTM zone). Affine transform maps pixel (x, y) to map (east, north). Two images are a pair only if bounds and grid match, or you have a logged, reversible resample. Library: rasterio (wraps GDAL).

4. Router (this is the agent)

If-then. Not a trained model. ISRO’s word “agentic” means: interpret the request, pick a tool from a fixed menu, run it, show the receipt. They said hidden chain-of-thought is not scored.

if files invalid                     → reject
if 1 image                          → single_image
if 2 images, different dates        → change
if 1 optical + 1 SAR, same place    → optical_sar
if question does not match files    → reject and explain
Do not train a router LLM You do not need a model that “configures roles.” The jobs are known. A JSON plan is the whole brain.

5. The three tools

Only place “AI” is allowed. Each tool is a function: images in, JSON facts out. Same door so the composer does not care which room ran.

Tool 1 · Single image (M4) · Scene 1

Question to lock: Describe the land-cover and major objects visible in this image.

Simplest version: land-cover scores (water, forest, urban, crop…) then a template caption: “This scene contains: water, forest.” VQA “is there water?” is just checking the water score. A heatmap is optional.

This is also the only room where a fine-tuned VLM may sit later. Today it can be a classifier or even a stub that is correct on the chosen demo image.

Tool 2 · Change (M5) · Scene 2, hero

Question to lock: Has the built-up area increased, decreased, or remained unchanged?

Simplest version: M3 already confirmed alignment. Subtract (or compare) the two images, threshold, paint changed pixels red, count area, emit increased / decreased / unchanged. Do not paste two screenshots into a chatbot.

Teach: image differencing If pixel values are comparable, |after - before| is large where the ground changed. Threshold that map, you get a mask. Convert pixel count × pixel size (from GeoTIFF transform) to hectares. Noise will fire on clouds and season. For 12 Sep pick a pair where the change is obvious (new buildings, a river shift). Later you can swap in a dual-encoder change network. Same JSON.

Tool 3 · Optical + SAR (M6) · Scene 3

Question to lock: Use the optical and SAR images together to identify built-up and water-covered regions.

Simplest version: a map from optical, a map from SAR, a combine rule (e.g. water if either says water, useful under cloud). UI toggle must show fused ≠ optical-only, or judges will say you ignored radar.

6. Composer and report

Code. If a fact is missing from JSON, it cannot appear in the sentence. Optional later: a small rewriter that may only polish grammar. Never let it look at the pixels and add objects.

Teaching: the ideas behind the boxes

Why this problem exists

ISRO and state agencies use satellite pictures for floods, farms, cities, forests, water. Today each AI tool does one job, and you need GIS skill to pick the model. A district officer cannot upload a file and ask in English. One optical photo is often not enough: clouds, night, and “what changed” need radar and a second date.

ISRO’s named product is SatQuery AI: an interactive assistant for single and paired remote-sensing images through text queries. Single-image Q&A is the baseline. The centre of gravity is paired work (before/after and optical+SAR). A generic LLM/VLM without satellite adaptation does not satisfy the statement.

Official listing (scraped copy): SIH26167 markdown. Portal: sih.gov.in.

Optical vs SAR

Optical (Sentinel-2, Cartosat)SAR (Sentinel-1, RISAT)
How it seesSunlight reflectedRadar pulse bounced back
NightNoYes
CloudsBlockedMostly sees through
Looks likeA photoSpeckled grey
Good forColour, vegetation, contextWater, structure, all-weather

If you convert SAR to a fake RGB and feed the same network you used for photos, you are treating radar as a camera. Preprocess them separately. That is why Tool 3 has two stems, even if each stem is simple.

Sentinel overview: Sentinel-1, Sentinel-2.

GeoTIFF, CRS, bands

Band = one channel. RGB is 3 bands. Sentinel-2 has more (red-edge, NIR…). SAR often has polarisations (VV, VH) as bands. “Stretch” means turning raw numbers into something visible (percentile stretch, not a phone auto-filter).

Pixel (i, j) → map coordinates using the affine transform. Your overlay must be converted back so it sits on the original image. If you skip this, the red blob is in the wrong valley.

Docs: GDAL GeoTIFF, rasterio quickstart.

VQA, captioning, grounding

  • VQA: question in, short answer out. Mandatory.
  • Captioning: one description. Pick this as your extra single-image task. Easier than grounding.
  • Grounding: “highlight the water body.” A box or mask. Stretch goal after 12 Sep.

Classic RSVQA (2018) did this without ChatGPT: CNN on the image, language encoder on the question, fuse, classify the answer. That is still a valid Tool 1. A VLM is a heavier way to do the same job.

RSVQA paper: arXiv:1911.07747. VRSBench: vrsbench.github.io.

Fine-tuning, adapters, LoRA

You need this vocabulary for the finale and for slide 3. You do not run it this week.

Pretrained model. Someone already trained a network on a huge pile of images or text. You start there instead of from random numbers.

Training from scratch. Random weights, your dataset only. Slow, needs a lot of data. Skip.

Full fine-tune. Take the pretrained model and update every weight on your satellite data. Needs a lot of GPU memory. Easy to overwrite the useful original knowledge. Usually more than a student team should do on a 7B VLM.

Freeze the backbone, train a head. Keep the pretrained vision encoder still. Train only a small classifier on top (land-cover). This is the honest 12-Sep-plus path for Tool 1 if you skip VLMs.

LoRA (Low-Rank Adaptation). Paper: Hu et al., 2021. You freeze the original weights W. Beside each big layer you add two tiny matrices A and B so the effective weight is W + B A. Only A and B train. Rank r (often 8 or 16) is how “wide” those stickers are. You store a small adapter file, not a copy of the whole model. At inference you can merge B A back into W.

Analogy: full fine-tune rewrites the textbook. LoRA adds sticky notes. The textbook stays. You can peel the notes off.

PEFT is Hugging Face’s library that implements LoRA and cousins: huggingface.co/docs/peft.

QLoRA is LoRA on a 4-bit quantised model so it fits a smaller GPU: arXiv:2305.14314. Useful if you only have a 16 GB card later.

What ISRO actually requires. “At least one visual or vision-language component must be fine-tuned or otherwise adapted” on BigEarthNet.txt or other open data. “Otherwise adapted” includes a land-cover classifier trained on BigEarthNet. A LoRA on a 1B VLM also counts. Training three VLMs does not match the architecture and will eat the demo.

The BigEarthNet.txt paper itself fine-tuned InternVL-3-1B with separate Sentinel-1 and Sentinel-2 stems, not a 13B chatbot. That is the size hint: arXiv:2603.29630.

4
Write the checker
M3 · day 2-4

Depends on: jobs 1-3. Used by the router before any tool runs.

  1. Script inspect.py path using rasterio. Print: width, height, band count, dtype, CRS, bounds, transform, nodata, any date tags.
  2. Guess modality: many bands / RGB-like → optical. 1-2 bands, float, Sentinel-1-ish metadata → SAR. If unsure, return unknown and let the UI ask.
  3. Function pair_compatible(a, b): same CRS, bounds overlap almost fully, height/width close. If not, return ok=False, reason="These images are not the same place (bounds differ)."
  4. Function preview(path) → png: percentile stretch, save an 8-bit PNG the website can show. For SAR, log-scale then stretch so it is not a black square.
  5. Tests: Pack A OK, Pack B pair OK, Pack C pair OK with modalities optical+SAR, Pack D reject.

7
Tool 2: before / after change
M5 · day 3-6

Depends on: jobs 2-4. Hero scene.

Locked question: Has the built-up area increased, decreased, or remained unchanged?

  1. Assume checker already said the pair is aligned. If shapes differ by a few pixels, resize the second to the first and put a warning in JSON.
  2. Read band 1 (or a grayscale of RGB). Compute diff = abs(after - before).
  3. Threshold (start at a percentile, e.g. top 10%). That binary map is the mask.
  4. Count mask pixels. Multiply by pixel width × height from the GeoTIFF transform. Convert m² to hectares.
  5. For the demo pair you chose because built-up grew, set answer_key: "increased". Optionally compare mean brightness in the mask on after vs before so it is not a hardcoded word.
  6. Save a red overlay PNG (mask painted on the after image).
  7. Return facts: answer_key, area_ha, class: "built-up", overlay file, confidence (start at 0.7 and lower it if the mask is noisy).

Done when: Pack B produces increased (or whatever is true), a red PNG, and an area number, every time.
